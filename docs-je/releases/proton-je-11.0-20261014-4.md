**Why this release:** the patches for upstream Wine went through a review pass; what they fix is unchanged. Patch 2 is smaller and also corrects the comment in `RtlWakeAddressAll()`, Wine's own (`82275b13a24`), that accepted the stale alert as the price of alerting outside the spinlock; its test, patch 3, loses a fallback that no Windows version runs. Patch 4's code is unchanged; its message now cites `934514db7c2`, the same fix for Wine's server-side mutexes, whose `kernel32:sync` check it makes pass with ntsync. Patch 5 tells the server about a mutex that is closed while still in use with a request of its own, `keep_inproc_sync`, sent from `close_inproc_sync()`, instead of a field in the `close_handle` and `dup_handle` requests, so no existing request and neither `NtClose()` nor `NtDuplicateObject()` changes any more. New: patch 6, a `kernel32:sync` test of that case, which fails with ntsync without patch 5 and passes on Windows 11. Measured before the release on Proton Experimental 20261014 with ntsync: `ntdll:sync` and `kernel32:sync` pass, 64- and 32-bit, where stock fails the new tests, and both new tests pass on Windows 11 ([patch pages](https://github.com/jegglest/proton-je/tree/proton-je-11.0-20261014-4/docs-je/patches)). Same base and same other commits as `-3`; the FSR 4 commits and Valve's Helldivers 2 fix move up one place.
